# Larastan baseline policy

## Purpose and ownership

`backend/phpstan-baseline.neon` is owned by Backend Engineering, with Security review for IAM, tenancy, assessment, result, finance, and data-integrity surfaces. It contains exact message regexes, identifiers, paths, and counts generated by PHPStan's supported baseline mechanism.

The baseline is temporary technical-debt accounting, not permission to introduce new static-analysis failures.

## Enforcement

- Current verified legacy errors = baseline.
- New error or increased count = CI failure.
- Reduced error count or unmatched entry = regenerate/reduce the baseline in the same change.
- Do not add directory-, namespace-, or error-category-wide ignores.
- Never baseline a plausible security, tenant-isolation, authorization, data-integrity, required-flow runtime, authentication, workspace-switching, finance, or result-integrity defect. Investigate and fix it first.

## Commands

Run from `backend`:

```sh
vendor/bin/phpstan analyse --memory-limit=1G --no-progress
```

After reviewed reductions only:

```sh
vendor/bin/phpstan analyse --memory-limit=1G --no-progress --generate-baseline=phpstan-baseline.neon
vendor/bin/phpstan analyse --memory-limit=1G --no-progress
```

Baseline removal is complete when the unbaselined analysis reports zero findings and `phpstan.neon` no longer needs the baseline include.
