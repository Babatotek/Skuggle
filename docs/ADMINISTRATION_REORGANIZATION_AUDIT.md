# Administration forensic audit and migration mapping

Source: `SKUGGLE_ADMINISTRATION_REORGANIZATION_PRD.md`, read before implementation, 8 September 2026. Scope: school tenant Administration; preserve existing assessment/server work.

## Findings before implementation

`routing/registry.ts` registers ten flat Administration destinations; `primaryNavigation.ts` exposes nine as persistent links. `WorkspaceShellChrome` additionally mounts `ModuleWorkspace`, which projects the old `lib/navigation.ts` groups as horizontal tabs. `SchoolStructureView` adds another tab row. School legacy IDs all resolve to an overview that fetches profile plus nine unrelated datasets. Users and roles routes both mount `AdministratorsView`; this is a membership screen, not a role editor. Automation, authentication policies and system configuration have distinct backend records but are incorrectly aliased to workflows/security.

## Architecture decisions

Use the established `/school/administration` prefix, one primary entry and nine domain landing pages. Category cards progressively disclose working capabilities. Keep compatibility route IDs where useful, change their URL and add redirects for old URLs. Correct legacy nav-ID targets individually. Preserve operational lookup APIs: similar controllers have different read permissions, response shapes and consumers. Reuse form engine rather than introducing another custom-field system. Do not claim missing role-definition CRUD, identifier engine, message-template delivery, webhook engine or generic tenant backup/import/export exists. These are product gaps, not grounds for placeholder pages. Existing workflow/security/integration modules store configuration records; navigation cannot turn them into execution engines.

## Security and performance audit

SchoolStructureController performs resource-specific read/write checks; scoped models bind reads/writes to TenantContext. Membership writes additionally require School Super Admin and preserve the last Super Admin. Forms use tenant context and audited writes. Branding uses public tenant storage prefixes. LookupCacheService documents tenant-scoped invalidation. Generic records use scoped models and audit writes, but accept arbitrary payload keys: credential-shaped extra fields must not be accepted into integration metadata. No tenant secret store or school integration credential UI was found; platform API credentials remain platform-owned. SchoolStructureView currently swallows list errors and requests unrelated data; capability routing must narrow fetches and expose errors. Landing pages must make no domain requests.

No files or business APIs are classified RETIRE without reference evidence. Retire only the competing rendered navigation composition and duplicate route destinations after compatibility mappings exist. Runtime tests and final acceptance evidence will be recorded separately.
